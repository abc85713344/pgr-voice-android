# 剧情听书：参考资料与功能设计

核查日期：2026-09-28。本文记录公开资料研究与本项目的设计建议，**不是功能已经交付或真机验收通过的声明**。本次查阅官方商店、项目仓库和 Android 文档，没有安装运行第三方听书软件，没有复制它们的代码、图片或音频。

**0.3.0 实际采用的方案：**独立大章续听与书签、三种支线方式、0.75×–2×、句内进度、定时暂停及系统媒体会话均已实现。为满足小节连续收听，未收录配音默认跳过并计数；解码失败暂停。全部听取将未接入导航的已收录台词放在本小节末，标注“补充片段（顺序未核实）”，不当作已确认的游戏路线。其他模式在未知连接处提示并接下一个明确小节。实际播放复用 Media3 ExoPlayer，媒体通知与控制使用 Android 系统 MediaSession；没有引入参考应用源码。以下调研中的备选方案不等于已交付行为，完整说明以《使用说明》和《实际测试范围》为准。

## 一、值得借鉴的产品

| 参考 | 已核实的功能或定位 | 本项目采用的思路 |
| --- | --- | --- |
| [Smart AudioBook Player 官方商店](https://play.google.com/store/apps/details?id=ak.alizandro.smartaudiobookplayer&hl=en) | 每本书分别保存进度；书签、播放历史、倍速与睡眠暂停；以未开始、正在听、已完成管理书库 | 大章节作为一本书；章节卡直接显示上回听到的位置；跳转前保存返回点 |
| [Voice 官方网站](https://voice.woitaschek.de/)与[源码仓库](https://github.com/PaulWoitaschek/Voice) | 面向本地音频；续听位置、书签、章节导航、睡眠定时、倍速；无需账号或强制云同步 | 保持离线使用，播放页只突出续听、目录、书签和播放控制；把睡眠定时作为单独设置 |
| [Audiobookshelf 仓库](https://github.com/advplyr/audiobookshelf)与[移动端仓库](https://github.com/advplyr/audiobookshelf-app) | 自建有声书与播客服务；按用户保存进度；支持章节和元数据管理；官方移动端需要连接服务端 | 借鉴章节元数据和播放状态分离的思路，不引入账号、服务器、云同步或下载站 |

Voice 仓库标示 GNU GPL v3。Audiobookshelf [服务端许可证](https://github.com/advplyr/audiobookshelf/blob/master/LICENSE)和[移动端许可证](https://github.com/advplyr/audiobookshelf-app/blob/master/LICENSE)也是 GNU GPL v3。Smart AudioBook Player 商店页面未提供可供本项目采用的开源许可证。本轮仅参考功能和交互；如将来需要纳入第三方源码，另行检查具体文件、版本和许可要求。

这些听书软件处理的主要是线性音轨。本项目含互斥分支、人物话题和待核实出口，因此不能把音频文件按名称排序后直接当成剧情顺序。下面的分支与进度规则属于针对本项目的设计。

## 二、本次用户明确要求

1. 不开游戏也能直接听现有配音包；进入听书不启动 OCR、屏幕捕获或自动点击，也不要求悬浮窗和无障碍权限。
2. 按大章节选书；当前大章的小章节按配音包内的顺序连播，小节之间不用再点播放。大章结束停止，由用户选择下一大章。
3. 每个大章各自记住上次的小节和台词。返回书库、换章或重启后显示“上回听到：小节名 · 第 N 句 · 角色 · 台词摘录”。
4. 保存命名书签，支持回到对应小节和台词。
5. 提供“全部听取”“手动选择”“默认第一个”三种分支方式。

听书进度与游戏配音进度独立。听完一章不能改变游戏跟随的位置、已选路线、OCR 定位或自动点击配置。同一时间只允许一个模式发声；从游戏配音切入听书时停止原有自动任务，让过期播放完成回调失效。

## 三、建议的界面与播放流程

沿用当前黑灰红色与章节场景封面，新增“听书”入口。书库卡显示大章节标题、开始／续听按钮和最后位置；没有听过时显示“尚未开始”，听完时显示“已听完”。

播放页上半部显示章节封面、小节标题、角色和当前台词；中部显示“第 N 句”和实际播放状态；下半部提供上一句、暂停／继续、下一句、目录、书签、分支方式。没有可靠时长时只显示句子进度，不显示编造的分钟数或装饰波形。

选择章节、打开书签列表和恢复记录均先静音展示。用户点“继续听”才播放。暂停后继续的语义应明确：首版若只保存到句级，就从这一句重新播放，并在界面说明“从当前句开头续听”；若后续提供音频内续播，则另存毫秒偏移，不能只靠总播放时间反推台词。

目录列出配音包声明的小节顺序，展开后可看到台词与可听状态。点目录跳转前保留一个“返回上次位置”的临时记录，避免误触丢失续听点。

## 四、分支播放规则

| 方式 | 建议行为 | 对用户的提示 |
| --- | --- | --- |
| 全部听取 | 按配音包中的选项次序依次听各条支线，支线结束再进入下一支；最后回共同段。共同段只播放一次 | “正在听分支 2/3：选项名”；提醒可能提前听到不同路线的剧情 |
| 手动选择 | 到选择点暂停，展示选项；用户选好后继续。返回人物或话题菜单时同样等待选择 | “等待选择分支”，锁屏通知可回到应用选择 |
| 默认第一个 | 在当前条件允许的选项中按包内顺序选择第一个；不随机、不跨过条件强选 | 显示实际选中的分支名称 |

建议首次默认“手动选择”，保留上一次主动选择的方式；用户希望连续收听时可以一次改成“全部听取”或“默认第一个”。更改方式先暂停，并从当前位置重新计算后续，不重放已听过的前文。

全听的必要约束：

- 依据 `NextId`、选择点、路线范围、返回点和汇合点遍历，不依据文件名或 `Nodes` 数组下标串接。
- 互斥分支的状态各自从同一选择前状态展开；A 路线的条件事实不能污染 B 路线。嵌套分支需要保存待听队列和返回栈。
- 人物话题菜单有返回循环，同一轮全听每个选项最多进入一次；所有可听话题结束才沿已核实的出口继续。不能以“再次回到菜单”作为无限重播理由。
- 支线正文已核实但出口未核实，应听到已知边界后暂停；显示“本段已结束，后续衔接待确认”。用户可选下一支或下一小节，不能假设未知出口等于共同线。
- 没有任何可用选项时暂停说明原因，不悄悄跳过整段。归档节点不加入默认连播。
- 保存当前位置时同时保存分支方式、已听分支、待听分支和必要的返回上下文；否则全听模式重启后容易漏播或重复。

## 五、续听与书签保存

自动续听点与手动书签分开：每个大章一个自动续听点；书签可有多个，并且有名称、创建时间、小节、角色和台词摘录。删除书签不清除自动进度；重听也不删除收藏。

建议保存稳定的包 ID、大章 ID、小节 ID、节点 ID、导航指纹、分支方式和路线快照。第 N 句仅供显示，不能作为恢复的唯一依据。命名书签保存同样的路线上下文，保证在“全部听取”中回到某条支线后仍有正确后续。

每句开始、自然播放结束、用户暂停、跳句、跳小节、切章和系统中断时更新进度；文件采用临时写入后替换并保留最近有效备份。启动恢复不自动发声。

仅更新音频时保留听书位置。剧情图变化时使用明确的节点迁移或经过验证的兼容规则；旧节点已删而无法迁移时保留旧记录并提示重新选小节，不悄悄回到第一句。后续存档导出若加入听书，应明确包含续听点与听书书签，不能沿用旧版“章节存档”的名称却漏掉新增数据。

## 六、后台与系统音频

Android 官方建议把播放器与媒体会话置于后台播放服务中，以便锁屏和切出界面后继续播放，并让系统媒体面板、耳机按键控制同一播放状态。服务使用 `mediaPlayback` 前台服务类型。参考 [MediaSessionService 后台播放](https://developer.android.com/media/media3/session/background-playback)与[媒体会话控制](https://developer.android.com/media/media3/session/control-playback)。

本工程已使用 Media3 ExoPlayer，并已声明媒体播放前台服务权限。听书应拥有独立的队列与媒体会话；可以复用已有耳机断开和音频中断处理经验，但不要复用游戏跟随的路线状态。用户从应用主动开始收听后再建立播放服务，不能在开机或进程恢复时自行发声。

建议首版可靠性要求：

- 通知栏及锁屏显示“大章 · 小节”和当前台词摘要，提供暂停／继续、上一句、下一句。所有入口走同一条串行播放命令通路，旧通知不能控制新章的旧节点。
- 拔出有线耳机或蓝牙断开、音频转为外放时暂停；重新连上不自行恢复。Android 对此提供 `ACTION_AUDIO_BECOMING_NOISY`，见[音频输出变化](https://developer.android.com/media/platform/output)。
- 通话或音频焦点丢失时暂停并保存位置。听书属于语音内容，默认暂停比持续压低音量更容易避免漏听；永久失焦后由用户明确继续。听书与游戏的同时播放策略应分开，见[音频焦点](https://developer.android.com/media/optimize/audio-focus)。
- 正常锁屏不停止听书；退出听书、播放完成、不可恢复错误则停止播放服务并释放资源。重启、权限恢复或切屏只恢复界面状态。
- 厂商省电限制、蓝牙媒体键和长时间息屏仍需真机验证，模拟器运行不作为耗电或后台稳定性结论。

## 七、缺音、原声与未核实段落

区分“没有需要朗读的正文”“音频缺失”和“剧情出口未核实”，不能统一当成播放完成。

建议默认在缺少可朗读音频时暂停，保留台词并给出“跳过本句继续”与“返回目录”。可以另加“连续跳过缺音”开关；开启后在页面记录跳过数量和最近缺句，但不把缺失内容标成已听。

明确 `not-spoken` 的节点可作为无声过渡继续，并显示必要文本。解码失败或文件损坏需暂停报错，不能触发自然结束事件并跨到下一句。

原版游戏原声不会因为离线听书而自动获得。包中没有相应原声音频时显示“此段仅有游戏原声／当前包未提供”，由用户选择跳过或看文字；不要偷偷录制游戏，也不要把静音等待伪装成已播放原声。`gap` 或未核实的路线边界保留明确暂停，不用缺音跳过规则穿越未知剧情。

## 八、可选完善项与优先顺序

| 优先级 | 功能 | 建议范围 |
| --- | --- | --- |
| 本次必需 | 大章选书、小节连播、每章续听、书签、三种分支 | 完整实现并测试独立进度和路线正确性 |
| 首版强烈建议 | 媒体通知／锁屏、耳机断开暂停、错误与缺音提示 | 保证能当日常听书播放器使用 |
| 可选完善 | 睡眠定时 | 15／30／60 分钟、听完本小节；到时直接暂停并保存位置，或明确选择“读完当前句再停” |
| 可选完善 | 倍速与句间停顿 | 先提供有限的常用档；保持语音可懂度，并按实际完成回调推进 |
| 可选完善 | 音频内续播、短暂回退、返回误触前位置 | 逐句素材优先保证句级恢复，不以复杂时间轴拖延核心功能 |
| 暂不加入 | 账号、云同步、在线听书搜索、外部下载站、自动采集音频 | 与现有离线配音包体系无关 |

睡眠定时属于 Voice 和 Smart AudioBook Player 都有的产品方向；上表具体档位与本小节结束行为是本项目建议，不表示照搬某款软件的实现。

## 九、验收用例

1. 大章 A 连续跨过两个小节，切到 B 播放后再回 A，恢复到原小节和原句；游戏配音进度保持原样。
2. 暂停、停止、下一句、切书、重启均不会出现旧音频完成回调推进新章；暂停时点击两次继续也只启动一次。
3. 全听 A／B 两分支时，A、B 各一次、共同段一次；嵌套分支、话题返回菜单不会无限循环。
4. 手选遇分支停；第一个模式遵守条件；没有可用选项或未知出口时给出可操作提示。
5. 在第二条支线保存书签，切书并重启后恢复，台词和后续待听分支一致；删除书签不丢续听点。
6. 无声节点、音频缺失、坏音频、原声段和剧情断点分别表现符合说明；整节无音频也不忙循环或假报已听完。
7. 息屏、通知按钮、耳机键、耳机拔出、蓝牙断开、其他应用抢焦点、睡眠定时均保持进度，且暂停后不自行发声。
8. 同导航图音频更新保留进度；图变化能迁移或明确提示；损坏的主存档可回退备份。
9. 真机至少一次长时间锁屏与前后台切换测试，记录延迟、进度恢复、音频中断和电量情况；未完成的项目列为待验证。
